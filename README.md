# Альфред — помощник при изменениях рейса

Учебный прототип для кейса TravelTech. Показывает, как задержка или отмена рейса влияет на общий план поездки и какие варианты можно предложить группе.

## Запуск

Откройте эту папку в VS Code и в терминале выполните:

```bash
python3 server.py
```

Затем откройте [http://localhost:8000](http://localhost:8000). Установка пакетов не требуется. Локальный API доступен по адресу `http://localhost:8000/api/flight-status?scenario=delay`.

## Сценарий демонстрации

1. Нажмите «Задержка» — увидите конфликт с трансфером и два варианта.
2. Нажмите «Выбрать» — обновится общий план, включая прогулку.
3. Включите «Оффлайн», затем выберите «Отмена». Уведомление будет ждать подключения.
4. Вернитесь «В сеть» — уведомление появится.

Данные демонстрационные. Прототип не оформляет бронирования, не проверяет наличие мест у поставщиков и не собирает паспортные данные.

## Как устроен прототип

```text
JSON со статусами → локальный API → интерфейс поездки
                                      ↓
                            конфликт с маршрутом
                                      ↓
                         варианты → выбор → новый план
```

- `server.py` отдаёт статические файлы и ответ `/api/flight-status`. Ответ включает идентификатор рейса, плановое время, статус, время обновления у источника и время получения события. Это показывает возможное запаздывание данных.
- `data/flight-statuses.json` содержит три сценария: рейс по расписанию, задержка и отмена. Время записано в ISO 8601 со смещением часового пояса.
- `src/app.js` показывает последствия для маршрута и варианты для трёх участников с багажом. Неподходящий вариант отмечен отдельно. После выбора обновляются рейс, трансфер, заселение и прогулка.
- Переключатель «Оффлайн» имитирует недоступность клиента: событие сохраняется локально в браузере и показывается после возвращения в сеть.

## Границы демонстрации

Варианты, цены, количество мест и визовые условия подготовлены заранее. Прототип показывает, **какие проверки нужны**, но не подтверждает их через внешние сервисы. Перед реальным бронированием потребуются запрос к поставщику, повторная проверка доступности и подтверждение пользователя. Паспортные данные здесь отсутствуют; в рабочей системе их нужно передавать только при необходимости и удалять по окончании цели обработки.

Для подключения настоящего поставщика достаточно заменить источник данных в `server.py`, сохранив формат ответа API. Следующий этап — вынести подбор вариантов в отдельный сервис с правилами по времени пересадки, багажу, визам и участникам группы.

Выбор маршрута сохраняется после перезагрузки. Кнопка «Сбросить» возвращает исходную поездку. В сценарии задержки варианты с запасом менее 60 минут после ожидаемого прилёта скрываются. На GitHub Pages демо может работать без Python: статическая версия читает тот же JSON.
